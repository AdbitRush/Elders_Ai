# IMAGES — Golden Games / BrainPlay (Elders_Ai)

**What this file is for.** Every picture in the app, what it is *supposed* to
show, and where it appears. The current set was generated by a free model
(Pollinations) and the owner's verdict is that it looks bad — this file is the
brief for replacing it, not a record of how it was made.

Keep the file names exactly as they are. The app builds its paths from the
game id, so a new picture at the same path needs no code change.

---

## Why the current set looks wrong

It is not that any single picture is bad. It is that **the 27 cards are in
three different visual languages at once**, and the eye reads the grid as a
mess before it reads any one card:

1. **Warm lifestyle photographs of older people** — memory, math, recall.
2. **Cold neon studio graphics on black** — sequence, numseq, digitspan, blocks.
3. **Flat-lay still life on a warm surface** — wordsearch, sudoku, letters.

Put a golden-hour photograph of a smiling woman next to a black-background
neon "7 3 9" and neither one survives. On top of that, the free model renders
elderly faces badly — the exact subject the first group depends on — and it
cannot spell, so every card meant to show letters or numbers shows nonsense.

## The fix: pick group 3 and apply it to all 27

One **still life** per game: the objects that game is played with, on the same
table, in the same light. This is the right choice for three reasons, not just
for consistency:

- **No faces.** Faces are what the model gets worst, and they are avoidable.
- **No text.** Any card needing a readable word or number is a card the model
  will fail. Objects carry the meaning instead: number *tiles*, not printed
  digits. Where a digit is unavoidable, keep it to one or two large ones.
- **It ages well.** A photograph of a person dates and has to feel like the
  right person; a well-lit object on a table does not.

### The recipe, identical for all 27

> A still life of **[the objects]**, arranged on a dark green baize table with
> a warm walnut edge visible at one side. Single soft light from the upper
> left, deep soft shadows, dark background falling off to near-black at the
> corners. Warm gold colour grade. Shot slightly from above, about 45 degrees.
> No people, no hands, no text, no logos. Photographic, not illustrated.

**Why this recipe:** the app is dark navy and gold, so a dark ground with a
warm key light drops the cards straight into the design instead of fighting
it. The 45-degree angle reads as "a table in front of you", which is what the
game is. And an identical table and light across all 27 is what makes the grid
look like one product.

**Format:** 3:2 landscape, 600×400 minimum (900×600 is better for retina),
JPEG, under ~120 KB each — 27 of them load on one screen.

**Test before committing the set:** put all 27 side by side at thumbnail size.
If any one of them jumps out, it is wrong, however good it looks alone.

## App icons

| File | Where it appears | What it should be |
|---|---|---|
| `images/icon.svg` | Favicon, manifest | Vector. A brain or puzzle mark in the app's gold on the dark navy, legible at 32px. |
| `images/icon-192.png` | PWA install, Android home screen | Same mark, 192×192, flat colour — no photograph, no gradient that turns to mud when the OS shrinks it. |
| `images/icon-512.png` | PWA splash | Same mark, 512×512. |
| `apple-touch-icon.png` | iOS home screen | Same mark, 180×180. iOS cannot use the SVG, which is why this exists as a separate PNG. |

The three PNGs and the SVG must be **the same mark**. They are currently
generated separately and drift is easy to miss.

## Images the app fetches rather than stores

| Where | Source | Leave alone? |
|---|---|---|
| Flags game | `flagcdn.com/w320/<code>.png` | **Yes.** Real national flags, correct and free. Do not replace with generated ones — a generated flag is a wrong flag. |
| Card fallback | `image.pollinations.ai`, in each card's `onerror` | Once a local `images/cards/<id>.jpg` exists and loads, this never fires. Worth deleting from `index.html` after the new set lands — it is 28 long URLs of dead weight. |

## Order to work in

1. **Three test cards first** — `sudoku`, `blocks`, `safari`. They are the
   three hardest cases (printed grid, abstract shape, living creature). If the
   recipe holds across those three it holds across the rest.
2. The remaining 24 cards.
3. The icon set, once, as one mark in four sizes.
4. Delete the Pollinations fallbacks from `index.html`.

Bump `ASSET_V` and the `sw.js` cache version when the new set lands, or
returning players keep the old pictures from their service-worker cache.
